# perception

トップページの背景で動かしている、点群の認識・追跡・経路計画の処理です。
Rust で書き、WebAssembly（`../perception.wasm`）にしてブラウザで実行しています。
描画と操作の受け付けは `../hero-fx.js` が行います。

LiDAR の点群はシミュレーションで作っています。実在のデータは使っていません。
このページのために書いた説明用の実装で、実機で使うための作り込み
（センサーの較正、自己位置推定、学習済みの検出器など）は入っていません。

## 処理の流れ

1 スキャン（0.1 秒）ごとに、次の順で処理します。

| ファイル | 内容 |
| --- | --- |
| `src/world.rs` | シミュレーターの世界。静止物、歩行者、ロボットの動き（正解データ） |
| `src/lidar.rs` | 回転式 LiDAR のシミュレーション。ビームが最初に当たる点を解析的に求める |
| `src/ground.rs` | 地面の推定。RANSAC で平面を当てはめ、各点の地面からの高さを求める |
| `src/cluster.rs` | クラスタリング。上から見たグリッドで、隣り合うセルをつないで物体に分ける |
| `src/track.rs` | 追跡。等速モデルのカルマンフィルタと、ハンガリアン法による対応付け |
| `src/plan.rs` | 点群から作る地図、コストマップ、A* による経路計画、経路をなぞる制御 |
| `src/grid.rs` | 経路計画用のグリッド、距離変換、A* |
| `src/lib.rs` | 全体の進行と、JavaScript から呼ぶ関数 |

認識側（`ground.rs` 以降）は、シミュレーターの正解を見ません。入力は点群と、
ロボット自身の位置と向きだけです（自己位置は分かっているものとしています）。

## 確認

シミュレーターの正解と見比べるテストがあります。

```sh
cargo test --release -- --nocapture
```

歩行者 5 人を 120 秒追跡したときの結果は、次のとおりです（56 本 × 1,300 方位の設定）。

- 見えている歩行者のうち、0.5 m 以内に追跡があった割合: 99 %
- 位置の誤差（RMS）: 0.06 m
- 歩行者のいない場所に出た追跡: 0 件
- ID の入れ替わり: 2 回（2 人が 0.6 m まで近づいて、1 つのクラスタになったとき）

経路計画は、次のことを確かめています。

- 目的地を順に 6 か所指定して、静止物に衝突せずに到達する
- 目的地までの直線を箱でふさいでも、回り込んで到達する
- 走っている途中で 1.7 m 先に箱を置かれても、衝突せずに止まって回り込む
- 歩行者・障害物・目的地をでたらめに足し続けても（150 秒 × 12 通り）、異常終了も衝突もしない

## 限界

- 人かどうかは、クラスタの大きさだけで決めています。人と同じくらいの背丈の物体は区別できません。
  そのため、動いたものだけを追跡の結果として表示しています。
- 2 人が 0.5 m ほどまで近づくと 1 つのクラスタになり、離れたあとに ID が入れ替わることがあります。
- センサーの高さは 1.9 m で、下向きのビームは 25 度までです。ロボットのすぐ近くの低い物体は見えません
  （一度見た物体は地図に残るので、近づいても避けられます）。

## ビルド

```sh
rustup target add wasm32-unknown-unknown   # 初回だけ
./build.sh
```

外部のクレートは使っていません。
